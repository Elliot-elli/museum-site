### 4.1 `verify_domain.js` 的 7 项判据

| ID | 检查 | 判据要点 |
|---|---|---|
| D1 | 境内 DNS 双解析器可解析 | 阿里 alidns + 腾讯 doh.pub 都要解出 A 记录 |
| D2 | 解析链指向本项目 | CNAME→`museum-site-cwb.pages.dev`（外部 DNS 路线）**或** A 全属 Cloudflare（NS 托管路线） |
| D3 | HTTPS 200 且证书有效 | 证书 SAN 覆盖该主机名 |
| D4 | 内容与基线逐字节一致 | md5 必须 = `770aefac5f11a473d959df9c18e00a9c` |
| D5 | 微信 UA 无拦截 | iOS + Android **双微信 UA** 的 md5 与普通 UA **完全相同** |
| D6 | www → apex 301/308 | 且必须保留路径与查询串；不配 www 时加 `--no-www` 记 SKIP |
| D7 | 真实浏览器渲染 | JS 0 错误、3 个 tab、切 tab 后主图加载成功、无横向溢出 |

> **D5 的判据设计**：不写「正文够长」，写「微信 UA 的字节与普通 UA 的**完全相同**」。
> 后者在拦截页本身够长时会误判为通过 —— 这是 11.12 遗留的判据写法问题，本轮已改。

### 4.2 脚本自检发现的真 bug（已修）

写自检时发现 `detectRoute` 有个**永真漏洞**：

> CNAME 指向**别人的** Pages 项目时，因为任何 `*.pages.dev` 的 A 记录都是 Cloudflare IP，
> 原逻辑会掉进「A 全属 Cloudflare」分支 → **误判为通过**。
> 而这正是「绑错站」—— 你的域名指向了另一个站，验收却告诉你 OK。

修法：**有 CNAME 就以 CNAME 为准，不看 A 记录**。已由 `S7` 反向用例守住。

## 八、为什么保留 `wrangler.jsonc`（原 🟢 待办的结论）

原待办写的是「删掉，纯冗余」。**我的结论是保留**，理由：

1. **Cloudflare 2026 改版后默认入口是 Workers**，Pages 降级为「旧版工作流」。
   这份文件是迁 Workers 时的**可用备份**，已同步好 `name` 与 `assets.directory`。
2. **走 Pages 路线时它被完全忽略**，对当前部署**零影响**（今天构建已验证：带它构建正常、md5 不变）。
3. 删除它**没有任何收益**，却拆掉一个对冲。

→ 结论：**留着**。若将来确定长期用 Pages 且不再考虑迁移，再删不迟。
